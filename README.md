# pipeline-onboard

Pipeline 型工具（多平台分发/多智能体流水线/后台协同类）接入工作流的阶梯方法论：工具价值不在「AI 有多聪明」，而在把工作流里重复的那一截砍掉——先砍分发、再砍排期、最后才碰互动和变现，顺序反了多半部署两周吃灰。

一句话：**分发 → 排期 → 互动 → 变现，顺序不可跳。每一步的稳定性是下一步的前提，跳级 = 把"未验证的前提"当"已验证的事实"用。**

## 方法论底座（源自 AiToEarn 拆解）

- 奥卡姆剃刀：剥掉「AI Agent/全链路/协同编排」，本质是一个「内容流水线收纳箱」——四件重复活（做内容/发平台/回评论/接广告）塞进同一后台
- 四智能体：Create（创作）/Publish（发布）/Engage（互动）/Monetize（变现），一人指挥 AI 干五个人的活
- 分发：一次创作同步 14+ 平台（抖音/小红书/B站/视频号/公众号 + TikTok/YouTube/Instagram/X/Facebook/Threads/Pinterest/LinkedIn），自动适配画幅/文案/封面 + 日历排期
- 互动：不只发还「挖」——识别「求链接」「怎么买」高转化信号优先接住 + 声量监测 + 热点追踪
- 变现：内置任务市场，CPS/CPE/CPM 三种计费
- 开源边界：MIT 协议、GitHub 约 2.6 万 Star、Docker 自托管 + MCP 协议接入 Claude/Cursor；但任务市场与收益结算走官方服务器——「开源」但没完全开源

## 解决什么

| 痛点 | 本技能的做法 |
|---|---|
| 这类工具到底该不该上 | 判断闸门：≥3 平台 + 每周固定产出 + 回本 ≤8 周，三条不齐别碰；部署前必做开源边界检查（自托管能干什么/什么走官方/数据归属） |
| 部署两周就吃灰 | 单环节切入（分发最优：可逆/可量化/低风险）+ 数字验收（≤50% 耗时且零事故，连续 2 周）；MCP 接入消除入口摩擦（切窗口次数=0） |
| 工具上了但没拿到杠杆 | 节奏改造：把发布变日历不是动作（覆盖率≥7 天无空档/临时决策=0/质量方差降）——批生产+自动跑才是杠杆点，工具只是让它可行 |
| 自动回评论翻车 | 四级分级（高意向/中性/负面/灌水）写成配置；高意向 100% 人过一眼、负面 AI 零发出（硬线）；每周抽查分类正确率防漂移；翻车处置 L1-L3 |
| "开源"被宣传口径误导 | 开源边界检查清单：完全可控/走官方/数据归属三栏必填；核心功能走官方 = 按托管服务重新定价（含数据主权风险） |
| 直奔变现踩坑 | 变现三前置（分发/节奏/兜底各≥2 周稳定）+ 最小任务走完结算全链 + 口径以官方规则和结算记录为准（不一致即停） |
| 矩阵号铺量翻车 | 排期密度检查（单平台单日≤3 条/单账号单日≤2 条）+ 限流信号监控（曝光骤降=被限，降密度重来） |

## 安装

复制本目录到 `~/.agents/skills/`（或你的 Skill 加载路径）即可。

## 自检

```bash
python scripts/validate.py tests/sample_good.json   # 必须 exit 0
python scripts/validate.py tests/sample_bad.json    # 必须 exit 1
```
