# 人工兜底分级：AI 对外发言的最后一秒留给人

> 核心：**评论自动回复是效率最高的功能，也是最容易翻车的功能。** 翻车的根因几乎都不是"AI 说得不好"，而是"该人审的没审、不该全自动的全自动了"——分级错了，不是 AI 错了。

## 一、评论四分类判据

| 类别 | 判据（关键词+意图） | 典型 | 处置 |
|---|---|---|---|
| **高意向** | 购买/获取意图：求链接/怎么买/多少钱/在哪买/求同款/求资料/怎么联系 + 变体（emoji 替代、错别字、拼音缩写） | "链接求""怎么入手""有渠道吗" | AI 拟稿 → **人过一眼** → 发 |
| **中性提问** | 功能/用法/事实询问，无购买意图 | "这个用什么做的""支持 xx 吗""教程有吗" | AI 拟稿 → 人批量过 → 发 |
| **负面/投诉** | 不满/质疑/维权/负面体验 + 任何可能升级的语气 | "质量这么差""退货""你们是不是骗子""举报了" | **人全权处理，AI 零参与**（连拟稿都不给） |
| **灌水/闲聊** | 无实质信息：纯表情/打卡/玩梗/无关闲聊 | "+1""哈哈哈哈""打卡" | 全自动（自动点赞或固定话术） |

### 变体识别（高意向最容易漏的）

```
漏检高发区（分类器最弱处）：
  1. 间接表达："这看着不错，有类似的吗"（意向在"类似"里）
  2. 试探性："你们接定制不"（意向在问句里，答错=丢单）
  3. 多意图混合："这个怎么买？另外你们家 xx 质量一般"（高意向+负面混合 → 升级给人，
     因为含负面成分，按"就高不就低"原则处理）
  4. 跨评论串联：上一条"这做的不错"，下一条"怎么卖"（单条分类会漏，
     需要按用户维度聚合判断）
原则：分类不确定时，升级给人（不确定=按高一档处理）。
  宁多审 10 条高意向（多花 5 分钟），不漏 1 条负面（5 分钟省不下公关事故）。
```

## 二、"最后一秒留给人"的执行机制

```
不是"人偶尔看看"，是机制保证：
1. 分级规则写成配置（工具内规则/分类器 prompt），不是每次人肉判断
   - 配置示例：
     含 [求链接,怎么买,多少钱,在哪买,求同款,求资料,怎么联系,接定制] → 高意向
     含 [差,退货,骗,举报,投诉,退款,垃圾,维权] → 负面
     长度 <8 字 且 无问号 且 无购买词 → 灌水
     其余 → 中性
2. 执行闸门：
   高意向/中性 → AI 生成回复 → 进"待确认队列"（不是直接发）
   负面 → 进"人工队列"（AI 连草稿都不出，人写）
   灌水 → 直接执行
3. 人的动作只有两个：
   过待确认队列（点"发"或"改"）——高意向逐条，中性批量扫
   处理人工队列——负面逐条
4. 审计字段（每条评论记录）：
   分类结果 / AI 草稿 / 人是否修改 / 修改内容 / 发出时间
   → 每周抽查用（见下）
```

**"人过一眼"不是走形式**：过一眼的价值 = 拦"AI 说得对但时机不对"（用户在气头上你发"亲，链接在这~"）和"AI 说得对但信息过时"（链接已下架）。这两类错，AI 自己永远发现不了（它没有"时机"和"现状"的实时感）。

## 三、分类器漂移检测（每周 15 分钟）

```
为什么需要：平台语料在变（新梗/新黑话/新变体），分类规则写死后会漂移
  ——上个月识别"求链接"，这个月用户发"蹲一个"，分类器全判成灌水。
每周抽查法：
  1. 随机抽 30 条本周已分类评论（每类至少 5 条）
  2. 人重新分类，对比分类器结果
  3. 算分类正确率：
     高意向类正确率 <95% → 漏意向 = 丢单，立即补规则（把漏检的变体加进配置）
     负面类正确率 <98% → 漏负面 = 公关风险，最高优先级修（负面漏检一条 = 事故）
     灌水类误判率 >20% → 实质内容被当灌水 = 用户被敷衍，补规则
  4. 连续 2 周正确率不升 → 规则方法到头了（变体太多），
     换方案：让大模型做分类（每周跑一次全量重分类）或收紧分级（更多类别转人审）
```

**硬指标（破一次即回炉）**：
```
[ ] 高意向评论 100% 经人确认（从审计字段查，不凭记忆）
[ ] 负面评论 AI 发出数 = 0（只要 ≠0，立刻停自动回复，查分类器，全量人审一周）
[ ] 灌水全自动的评论中，用户投诉数 = 0（有投诉 = 分级错，那条评论升级复盘）
```

## 四、翻车案例处置（发生后的标准动作）

```
翻车分级：
  L1 轻微（措辞不当但无实质错误，用户已划过）
    → 记录进翻车库（评论原文+分类结果+AI 回复+错在哪），补规则
  L2 中度（信息错误/时机错误，用户看到了并回复质疑）
    → 24h 内人工补救（人发更正/道歉，不用 AI 发——补救本身就是人做的事）
    → 翻车库记录 + 查根因（分类错？规则漏？AI 幻觉？）
  L3 严重（负面评论被 AI 回复/敏感词/公关事故）
    → 立即：删 AI 回复（平台允许的话）+ 人工处理原评论 + 停自动回复
    → 复盘：哪条规则漏的？为什么没进人审队列？
    → 机制修复：该类型永久转人审（从"分级"变"白名单全自动"，
      即：默认人审，只有明确安全的类型才全自动——翻车后的保守方向）
```

**翻车库的作用**（与 work-tri-layer 的翻车记录同构）：
```
每条翻车记录 = 一个"该类型评论的正确处置"样本
  积累 20 条 → 分类规则从"关键词表"升级为"案例库+规则"（大模型分类时当 few-shot）
  积累 50 条 → 你的"互动处置 SOP"成形——这个东西比工具值钱
  （换工具翻车库还在；工具停更你的 SOP 还能跑）
```

## 五、矩阵号场景的分级放大

```
单账号：高意向评论可能 0-5 条/天，人审轻松
矩阵号（N 账号×多平台）：高意向评论可能 50+ 条/天，人审成了瓶颈
放大策略（按序加）：
  1. 批处理：高意向拟稿按"话术模板"收敛（同类意向同一套模板，人只过变量部分）
     → 人审从"读完整句"变"扫 3 个变量"（产品名/价格/链接），5 分钟过 30 条
  2. 置信度分流：分类置信度 >0.95 且 命中过 3 次以上的模板 → 抽样人审（10%）
     置信度低或新变体 → 全人审
  3. 红线不变：负面类永远全人审，矩阵号也不例外（账号越多，一个公关事故影响面越大）
原则：放大的是"人审的效率"，不是"人审的覆盖"——覆盖率永远 100%，变的是单位成本。
```
