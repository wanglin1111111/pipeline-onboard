# 坑位清单

## 单平台低频硬上

**坑**：只在 1-2 个平台发、一周更一条，看到"14+ 平台分发"心动，部署了。
**问题**：部署成本是固定的（环境+账号接入+学习），收益随"每周发布动作数"走——一周 1 条内容摊 3 小时的维护成本 = 每条内容多付 3 小时。部署成本 > 收益是数学必然，不是执行力问题。
**对策**：闸门两条件（≥3 平台 + 每周固定产出）任一不满足 = 别碰；回本周期算出来 >8 周 = 别碰。等你的发布频率上来了再上（那时工具是放大器，不是负担）。

## 全盘替换（同时切 3 个环节）

**坑**："既然部署了，创作/分发/互动一起切，一步到位。"
**问题**：同时切 = 出问题无法归因（质量降了是创作环节切的？数据降了是互动环节切的？）；验证失败 = 全链路回滚 = 部署白费。而且创作环节质量敏感（切错归因难），互动环节易翻车（切错出事故）——两个最高风险的环节放在第一周 = 第一周就翻车。
**对策**：验证期只切一个环节（分发最优：可逆、可量化、低风险）；跑通一周再切下一个。"一步到位"省的那 2 周，大概率以翻车 + 回滚还回去。

## 只做分发不做日历（杠杆没用上）

**坑**：分发切通了，省了上传的 20 分钟/条，然后……还是每天临时想"今天发什么"。
**问题**：工具的真正杠杆在节奏改造（批生产+自动跑），不在"批量上传器"——只切分发 = 拿到了 10% 的收益（省上传），丢了 90%（焦虑循环没断、质量波动没解决、储备机制没建）。而且分发切通后的"日历改造"是零边际成本的（日历视图就是工具自带的），不做 = 纯浪费已部署的能力。
**对策**：分发验收通过（≤50% 耗时+零事故）后的第一动作就是排满一周日历；验收三指标（覆盖率≥7 天无空档/临时决策=0/质量方差下降）连续 2 周。

## AI 全自动回高意向评论

**坑**：自动回复跑了一周，"求链接"的评论 AI 秒回，感觉效率拉满——直到某条"怎么买"AI 回了个已下架的链接。
**问题**：高意向评论是转化关键，"AI 说得对但信息过时/时机不对"这类错 AI 永远自己发现不了（它没有实时感和时机感）；丢单是隐性成本（你根本不知道这条没成单）。效率最高的功能翻一次车，丢的不是一单是"这套自动化的信任"。
**对策**：分级硬线——高意向 100% 进待确认队列，人过一眼才发（fallback-grading 的执行机制）；翻车一次 = 查根因（规则漏了哪个变体？信息过时是数据源问题？）+ 补规则，不是"AI 下次注意"。

## 把"开源"当"全可控"

**坑**：冲着"MIT 协议、可自托管"上的，部署完才发现任务市场、收益结算、热点数据全走官方服务器。
**问题**：宣传口径的"开源"和你要用的功能的"可控范围"是两回事——核心功能（尤其涉及数据的）走官方服务器 = 你的数据在别人的服务器上，工具停更/官方政策变 = 你的资产（粉丝数据、收益数据、素材）被卡。按"开源工具"的预期做决策，按"托管服务"的现实承受后果。
**对策**：部署前填开源边界检查清单（onboard-ladder 第二节）：逐项列"完全可控/走官方/数据归属"；你要用的核心功能在"走官方"列 = 按托管服务重新定价（含数据主权风险），不是按开源工具。

## 直奔变现（最常见的跳级）

**坑**：被"内置任务市场、按效果结算、不用找商家"吸引，分发还没稳就去接单了。
**问题**：变现依赖三件事稳定——内容质量（批量后没降）、账号权重（没被限流）、互动数据（真实）；前面不稳就接单 = 交付质量差 = 结算纠纷（按效果的结算口径对交付质量有隐性要求）+ 账号权重掉 = 连本带利赔。而且变现是数据主权风险最大的模块（收益数据、结算全在官方侧）。
**对策**：变现三前置（分发/节奏/兜底各 ≥2 周稳定+验收指标达标）全过才碰；先 1 个最小任务走完结算全链（接单→交付→结算→到账），口径和宣传对不上 = 停，查官方规则原文。

## MCP 不接（后台吃灰的经典路径）

**坑**：工具部署得好好的，分发/排期都在跑——但它还是"另一个后台"，每天要记得去。两周后开始忘，一个月后吃灰。
**问题**：入口摩擦是弃用的第一原因（mcp-integration 第一节的心理学路径）：独立后台依赖"想起来"，而"想起来"在忙碌中必然失败。工具能力没问题，入口位置错了（在你已有动作之外）。
**对策**：MCP 接入是长期使用的分水岭，不是"锦上添花"——分发跑通后 1-2 周内完成最小调用链（3 条全通）+ 3 个函数固化；验收 = 一周切窗口次数 0。MCP 接不了（工具不支持/你的助手不支持）→ 用降级方案但设 2 周期限，到期没恢复 = 吃灰概率高，换工具。

## 宣传口径当结算依据

**坑**：任务市场写"按效果结算 CPS/CPE/CPM"，接了几个任务，结算时发现口径和宣传不一致（CPS 按"成交"算，但"成交"的认定规则你没注意；CPM 按"曝光"算，但曝光统计口径是平台的）。
**问题**：涉及真实收益的事，宣传页、推文、工具界面文案都不是依据——结算以平台官方规则和实际结算记录为准。用宣传口径预期收益 = 用假设的数字做投入决策（加大投入/排期/接更多单）。
**对策**：第一个任务的意义就是"验证口径"——记录结算口径/数据归属/到账周期，逐条对照官方规则；不一致 = 停（不加大投入），找官方规则原文；规则原文找不到的口径 = 风险不可控，这个模块不碰。

## 矩阵号铺量当质量

**坑**：矩阵号模式一开，一次下发 20 条任务并行产出，量上去了——然后账号被限流、互动率掉、平台判定垃圾内容。
**问题**：铺量能力是这类工具的卖点（"适合矩阵号铺量"），但平台算法不认"你是 AI 批量产的"，只认"内容质量分布"——20 条同质内容堆同一天 = 算法视角的垃圾内容；矩阵号的正确姿势是"多内容×多时间×多账号分散"，不是"多任务×同时间"。
**对策**：铺量前查该工具的排期分散能力（能不能自动错开时间/账号）；排期密度检查：单平台单日 ≤3 条、单账号单日 ≤2 条（经验值，按平台算法调整）；铺量后 1 周盯限流信号（曝光骤降=被限），限流 = 降密度重来，不是"再等等会恢复"。

## 工具停更没预案（开源工具的尾部风险）

**坑**：用了三个月很顺手，某天发现仓库三个月没 commit、issue 不回复、某平台接口变了没人修——发布开始报错。
**问题**：开源工具的"可维护性"不在你买它的时候，在你用第三个月的时候；平台侧接口是持续变化的（尤其社交平台的反爬/接口策略），工具停更 = 每个平台接口变化都是一次故障。你的工作流（日历/批生产节奏）已经依赖它了，停更 = 工作流断供。
**对策**：每月扫一眼仓库活跃度（最近 commit/issue 响应）——3 个月无 commit = 进入"降级预案"（数据导出：素材/排期/粉丝数据能带走的先带走）；账号授权独立于工具（授权 token 在你手里，工具死了账号还在）；核心数据（内容素材库）定期导出到你自己控制的存储——**工作流可以依赖工具，资产不能**（与 work-tri-layer"轻流程重资产"同构）。

## 用"AI 有多聪明"当选择标准

**坑**：选工具时对比"它用了什么模型"（Grok/Veo/Seedance），选了模型最豪华的——然后发现发布稳定性、排期精度、兜底机制反而是最差的。
**问题**：这类工具的价值不在"AI 有多聪明"（创作环节的模型能力是其次的，且可替换——MCP 时代模型可以换着接），而在"把你工作流里重复的那一截砍掉"（发布/排期/互动的稳定性与精度）。选模型豪华但发布不稳的工具 = 为不需要的聪明付费，同时缺了真正需要的稳定。
**对策**：选择标准按"你切哪个环节"排——切分发 → 看发布稳定性（多平台成功率/定时精度/失败重试）；切互动 → 看分类准确率与兜底机制；切创作 → 才看模型能力（且模型能力看"能不能接你自己的模型"比"自带哪个"更重要）。
