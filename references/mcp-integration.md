# MCP 接入实操：从"另一个工具"到"工作流里的函数"

> 核心判据：**这一步决定整套方案能不能长期用下去。** "另一个工具"会被弃用（多一个后台 = 多一个要记得去的地方）；"工作流里的函数"不会（它长在你已有的动作里，写完文案顺手就发了）。

## 一、为什么 MCP 是分水岭（机制解释）

```
工具弃用的心理学路径：
  独立后台 → 每天要"想起来去" → 忙起来忘了 → 三天没去 → 心理账户里"它停了"
  → 再启动要重新登录/找入口 → 摩擦成本累积 → 永久弃用
  （部署两周吃灰的最典型路径，不是工具不好，是入口在你已有动作之外）

MCP 接入后的路径：
  你本来就在 Claude/Cursor 里写文案 → 写完一句"发到 ABC 平台" → 触发
  → 入口 = 你已有的动作本身 → 零"想起来"成本 → 长期存活
  （"另一个工具"变"工作流里的函数"：函数不需要被记得，它被调用）
```

**注意**：MCP 不是万能药——它解决的是"入口摩擦"，不解决"工具本身不好用"。工具分发能力不行，接进 MCP 也只是"高频地触发一个不行的工具"。MCP 接入应发生在分发环节已验证跑通之后（第 1 步验收过了），不是替代验证。

## 二、最小调用链（接入验收标准）

```
最小调用链 = 3 条，全通才算接入完成：
  L1 发布触发：
    对话内："把这段文案（指上文）发到 A/B/C 三个平台，明天上午 10:00"
    预期：工具执行 + 返回排期确认（日历可见）
    失败点排查：MCP 服务没起来 / 账号授权过期 / 平台参数没传对
  L2 状态查询：
    对话内："本周日历发我看一眼"
    预期：返回一周排期（含已发/待发/空档）
    失败点排查：查询接口权限 / 返回格式没解析
  L3 兜底协同：
    对话内："这条高意向评论（贴出来）帮我拟个回复"
    预期：AI 拟稿进"待确认队列"（注意：是进队列，不是直接发——
    兜底分级机制在 MCP 场景下不变，最后一秒还是留给人）
    失败点排查：拟稿接口 / 队列状态同步
```

**验收记录**：
```markdown
# MCP 接入验收 <日期>
L1 发布触发：通/不通（耗时 __ 秒，确认信息 __）
L2 状态查询：通/不通
L3 兜底协同：通/不通
切窗口次数（接入后一周实测）：__ 次（目标 0）
结论：接入完成 / 降级方案启用（见下）
```

## 三、3 个常用函数固化（接入后的第二周做）

```
函数 1：发布+排期（最高频）
  触发语模板："把 {文案引用} 发到 {平台列表}，{时间}"
  固化内容：平台列表默认值（你的主力 3 平台）、时间默认值（如"明早 10:00"）
  验收：一句话完成，不需要补充参数（补充参数=默认值没固化好）

函数 2：周日历检查
  触发语模板："本周排期+空档"
  固化内容：空档高亮、已发条的数据（互动数）附在排期后面
  验收：周一早上 30 秒看完一周状态（这是日历驱动的"仪表盘"）

函数 3：评论拟稿（进队列）
  触发语模板："拟回复：{评论原文}（分类：高意向/中性）"
  固化内容：拟稿话术风格（和你人审时改稿后的风格对齐——
  把你过去一周人审修改过的稿子喂给它当风格样本）
  验收：拟稿进队列（不是直接发）+ 你点"发"的间隔 <30 秒/条
```

**固化的本质**：把"每次要想的参数"变成"默认值"，把"你的偏好"变成"它的风格"——函数用 10 次后，它应该比第一次"更懂你"（默认值是你的习惯，风格是你的口吻）。用 10 次还和第一次一样 = 没固化，只是"快捷指令"。

## 四、"切窗口次数=0"的测量方法

```
测量（接入后一周，每天下班记一笔）：
  今日为"用这个工具"而切到它独立窗口/后台的次数：__
  原因记录：（MCP 没覆盖的场景/服务挂了/忘了用 MCP 走了老路）
周汇总：
  总次数 = __（目标 0，≤2 可接受且要查原因，>2 = MCP 接入不彻底）
原因分类：
  MCP 没覆盖（有些操作 MCP 没有对应函数）→ 补函数或接受该操作走窗口
  服务挂了 → 查稳定性（挂了几次？每次多久？超过阈值换部署方式）
  老路惯性 → 无技术原因，一周后应自然消失（不消失=函数触发语不顺口，改触发语）
```

## 五、接入失败的降级方案

```
按可用性降序：
  1. MCP 正常接入（首选）
  2. Webhook 触发（MCP 不可用时）：
     你的 AI 助手 → 调 HTTP 接口 → 工具执行
     限制：只能做"发指令"，状态查询要另想办法
     适合：函数 1（发布）够用，函数 2/3 走窗口（降级可接受）
  3. 手动触发 + 日历提醒：
     工具照常用，但加一个"每日 9:55 提醒我去后台确认排期"的日历事件
     限制：入口摩擦回来了，靠提醒硬扛
     适合：临时降级（MCP 服务修复期），不超过 2 周
     超过 2 周还在用降级方案 = 实质弃用，重估工具价值
降级原则：降级可以，降级不能"无期限"——每个降级方案设恢复期限（2 周），
  到期 MCP 还没修好 = 工具没长进你的工作流，吃灰概率高，考虑换工具。
```

## 六、多工具场景：MCP 不是只接一个

```
如果你后续接入多个 pipeline 类工具（不同平台组合/不同功能）：
  原则：每个工具只负责一个"函数域"（如 A 管国内平台发布，B 管海外平台发布）
  反例：两个工具都能发抖音 → 对话里说"发到抖音"触发哪个？→ 路由混乱
  判据：你的函数触发语应该唯一指向一个工具（"发到抖音"=A，"发到 TikTok"=B）
  触发语冲突了 → 说明工具职能重叠 → 合并或砍一个（重叠=维护成本×2，收益≈0）
```
