# 接入阶梯详解：闸门、边界、切入点、节奏

> 核心纪律：**分发 → 排期 → 互动 → 变现，顺序不可跳。** 跳级 = 部署两周吃灰的高危动作。

## 一、判断闸门画像表（第 0 步展开）

### 目标用户画像（两条同时满足才继续）

```
条件 1：平台数 ≥3
  判据：你现在"每周都要登录"的平台 ≥3 个（不是"注册过"）
  反例：注册了 8 个平台但实际只发 1 个 → 不满足

条件 2：每周固定产出
  判据：过去 4 周，每周产出 ≥3 条（或等量：≥3 次发布动作）
  判据来源：翻发布记录数数，不凭"我感觉挺多的"
  反例：一周更一条，但每条花 3 小时 → 不满足（频率不够，摊不平部署成本）
```

### 部署成本估算（别凭感觉，算一笔账）

```
一次性成本（小时）：
  部署（Docker/环境）：__ h
  账号接入（14 个平台里你用的 N 个，逐个授权/插件）：__ h
  学习（后台/日历/插件）：__ h
  合计 C0

每周维护成本：
  检查工具运行/处理异常/更新配置：__ h/周
  合计 Cw

收益（每周省下）：
  手工分发：单条 __ 分钟 × 每周 __ 条 × N 平台联动系数
  合计 S/周

回本周期 = C0 / S（周）
判据：
  回本 ≤4 周 → 值得上
  回本 4-8 周 → 看节奏改造能否放大 S（能→上，不能→缓）
  回本 >8 周 → 别上（这是"单平台低频"的数学必然）
```

**矩阵号场景**：如果你运营的是矩阵号（多账号多平台铺量），条件 1 的"3 个平台"按"账号×平台"的发布动作数算——矩阵号是这类工具收益最大的人群（一次创作→数十条任务并行产出的能力直接兑现）。

| 数据 | 存在哪 | 离开该工具能带走吗 |

- 结论：买的是"开源工具" / "开源壳+托管服务" / "托管服务"

## 三、单环节切入：选点原则

### 选点排序（按"最容易见效"）

| 优先级 | 环节 | 为什么 | 风险 |
|---|---|---|---|
| 1 | **分发/上传** | 重复机械、出错可逆（发错了可删可重发）、效果立刻可见（省的时间直接可数） | 低 |
| 2 | 排期 | 分发的自然延伸，日历视图直接配套 | 低 |
| 3 | 互动 | 容易翻车（对外发言），但收益明确（挖高意向） | 中-高 |
| 4 | 变现 | 涉及真实收益，依赖前面三环稳定 | 高 |
| — | 创作 | 最难切（质量敏感，见 taste-gate），通常是最后才考虑部分交出去 | 高 |

**为什么分发最优**：验证期需要"快速、可逆、可量化"——分发三条全占。创作环节质量敏感，切错了（质量下降）归因困难（是工具问题还是提示词问题还是模型问题），不适合当第一刀。

**事故分类**（回查时用）：
```
工具配置问题（授权失效/定时偏差）→ 修配置
平台限制问题（某平台接口收紧/插件被禁）→ 该平台回手工，其余保留
内容适配问题（画幅/封面错）→ 调适配规则
工具本身 bug → 查 issue 区，无解则该环节切回
```

## 四、日历改造：前后对照（第 2 步展开）

```
改造前（动作驱动）——典型一周：
  周一：临时想主题→做→发（2h）
  周三：突然想起来该发了→赶工→发（3h，质量差）
  周五：补发（1h）
  心理状态：每天醒来先焦虑"今天发什么"，发布节奏随情绪波动
  数据特征：发布间隔 1-3 天不等，内容质量波动大（赶工条数据差）

改造后（日历驱动）——典型一周：
  周一上午：批生产（一次产出 3-5 条，可并行/批量；创作环节可用"一次下发多条任务并行"能力）
  周一下午：日历排满（周一 10:00 A平台 / 周二 10:00 B平台 …… 一周 5-7 格全排）
  周二~周日：只做三件事——处理互动（兜底分级）/ 数据复盘 / 做下周储备
  心理状态：无"今天发什么"决策；空档=做储备，不是焦虑
  数据特征：发布间隔稳定（1 天/条±），内容质量稳定（都是批产的，不是赶工的）
```

**验收三指标（连续 2 周）**：
```
1. 日历覆盖率：≥7 天无空档（空档=临时决策=改造失败信号）
2. 临时决策次数：一周内"计划外临时决定发什么"= 0 次
3. 质量稳定性：批产条的互动数据方差 ≤ 改造前赶工条的方差（别用"感觉稳定"）
```

**判据**：工具只是让"批生产+自动跑"变得可行；**节奏改不改在你**——工具上线了但还在"每天临时想"，等于杠杆没装上（退化成"批量上传器"，只省了上传那 20 分钟，没拿到节奏改造的杠杆）。

## 五、跳级的后果（为什么顺序不可跳）

| 跳级动作 | 后果 |
|---|---|
| 直奔变现（最常见） | 内容质量没经过批量稳定性验证→接单后交付质量差→结算纠纷→账号权重掉→全链路崩；而且变现模块依赖官方服务器，数据主权风险最大 |
| 分发没稳就切互动 | 自动回复在高事故状态下运行→翻车评论发生在"内容还没人看"的阶段→工具直接被弃用（第一印象=翻车） |
| 日历没建就并行铺量 | 矩阵号一次铺 20 条无排期→全堆在同一天→算法判定垃圾→账号限流 |
| MCP 没接就全面铺开 | 工具还是"另一个后台"→每天要记得去→两周后吃灰（最典型的弃用路径） |

**顺序的本质**：每一步的稳定性是下一步的前提——分发稳→内容才值得排期；排期稳→互动才有稳定的流量可接；互动稳（人审机制验证过）→才敢碰对外收益。跳级 = 把"未验证的前提"当"已验证的事实"用。
